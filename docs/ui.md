## シンプルモード

- ジャンルの試聴（シンプルモードの設定画面、ジャンルのチップの下の「▷ ○○ のサンプルを聴く」と一言の説明 `GENRE_DESCRIPTIONS`）：
  - ジャンルのチップは雰囲気で絞り込む（`MOOD_GENRES` の順に並べ、合わないジャンルは隠す。開いた曲のジャンルが外れていても選んでいるジャンルは出す）。雰囲気を選び直して今のジャンルが合わなければ、合うジャンルの先頭に切り替える（テンポのプリセットもそのジャンルの BPM に）。
  - 説明文は `{TERMS のキー:文字}` と書いた所を用語のツールチップ付きの span にして表示する（`renderGenreDesc`）。
  - 選んでいるジャンル・雰囲気から `resolveSimpleMode` でパターンを選び、メロディを自動生成して `Playback.playSample()` で鳴らす。
  - ドラム・パーカッション・コード・ベース・パッド・シグネチャー・メロディをアレンジに関係なく同時に、`SAMPLE_SECONDS`（15 秒）鳴らして止める（`Playback.ts`）。テンポ・進行の長さ・拍子によらず同じ長さにするため（以前はコード進行1周＝4小節以上で、速いワルツの 4 秒ほどから 6/8バラードの 30 秒ほどまでばらついていた）。短い進行はループし、長い進行は途中で終わる。終わりの `SAMPLE_FADE_SECONDS`（2 秒）でマスターをフェードアウトする（`fadeOutMaster`。リミッターのあとのゲインなのでリバーブの響きも一緒に消える）。
  - 止める時刻は Transport の小節ではなくオーディオの時計（`Tone.getContext().setTimeout`）で決める（サンプル中にテンポを変えても長さが変わらない）。フェードしたマスターは止めたあとも絞ったまま（`holdMasterFade`。途中で止めたらその音量のまま）にし、残っている響きが戻ってこないようにする。次の再生・試聴・サンプルの開始で戻す（`resetMasterFade`）。
  - 各パートは AppState から読むので、鳴らしている間だけ `chordPattern` / `drumPattern` / `meter`（ジャンルの標準の拍子）/ `melodyNotes`（拍子を差し替えてから作る）を差し替え、`Playback.stop()` で元に戻す（曲の内容は変わらない）。
  - サンプル中にジャンルを選び直すとそのジャンルのサンプルに切り替わり、テンポを変えるとすぐ反映される。画面の切り替え（`stopSample()`）・生成・ほかの再生で止まる。
- シンプルモードの曲の長さは 32 小節（`SimpleScreen.ts` の `SIMPLE_SONG_BARS`。生成時・コード進行の差し替え時に設定する）。
- 「生成する」（生成後の「✦ 別の曲を生成する」は廃止した。選び直すときは「‹ 雰囲気・ジャンル・テンポを変更」で設定画面に戻って生成し直す）は、ピアノロールで作った内容を残す：メロディの入力方法が「自分で入力」ならメロディ（Aメロ・サビ）はそのまま（自動生成のときだけ作り直す）、オリジナルのドラム（`CUSTOM_DRUM_ID`）もそのまま（コード進行・サビの進行は選び直す）。残すものがあるときは「生成する」の下（`#s-keep-hint`）に出す。オリジナルのドラムをドラムの「↻ 再抽選」で置き換えるときは確かめる。「自分で入力」でメロディ（Aメロ・サビとも）に音がないまま「生成する」を押したときは、メロディなしで生成してよいか確かめる（`confirmEmptyMelody`。やめると何もしない）。
- 生成結果の「レイヤー差し替え」：メロディ・コード・ドラムのカードの「↻ 再抽選」は押したパートだけを選び直す（メロディは以前「↻ 再生成」）。どれも Aメロ・サビの両方が変わるので、見出しの横（`.field-hint`）とボタンの title に書く。カードの説明は Aメロ・サビの内容：メロディは音の数（「Aメロ 24音・サビ 26音」、Aメロとサビは別のメロディで、サビを入力していなければ「サビ 0音」。`melodySummary`。以前は再生成した回数の「フレーズA〜Z」で意味がなかった）、コードは「Aメロ：… ／ サビ：…」（サビの進行がなければ「（Aメロ・サビ共通）」）。
- シンプルモードの「生成された楽曲」の波形は実際の音声ではなく、周回ごとのパート数とドラムの強さから描いた表示用のもの。
- 生成後の「‹ 雰囲気・ジャンル・テンポを変更」（`#s-edit-settings`。以前の表示名は「設定を変更」で、何を変えるのかわかりにくく、文字だけのリンクで目立たなかった。今はシンプルモードの色の枠付きボタン `.back-to-setup`）：押すと、設定画面に戻ってもう一度「生成する」と今の曲（コード進行・メロディ・ドラムなど）が新しい曲に置き換わって消えることをダイアログ（`askChoice`。`confirmBackToSetup`）で知らせる。保存していない変更があれば「保存せずに戻る」「保存してから戻る」「キャンセル」、なければ「設定画面に戻る」「キャンセル」。戻るだけでは曲は消えない（置き換わるのは「生成する」を押したとき）。
- 生成後の再生の操作：「▷ 再生」「■ 停止」と再生位置・曲の長さ（`#s-time`。「0:12 / 1:00」）は「生成された楽曲」のカードの上（`.wave-head`）に置く（以前は情報バーの右端だけで見つけにくかった）。情報バーの再生ボタン（`#s-bar-transport`）はピアノロールタブのときだけ出す。停止ボタンは鳴っている間だけ出す。どちらも `data-simple-play` / `data-simple-stop` で同じ動き。
- 再生バー（波形 `#s-wave-area`）：クリック・ドラッグで、離した位置の小節の頭から再生する（`Playback.play({ fromBar })`。止まっていても再生を始める）。押している間・カーソルを乗せている間は、鳴らし始める位置に線と「○小節目 0:30」を出す（`showSeek`）。キーボードでは ← → で1小節ずつ、Home で先頭から（`role="slider"`）。
- 情報バーのキーとスケール（「キー A ナチュラルマイナー」）と、コードのカードのコード名（「Am - C - G - D」）には用語のツールチップを付ける（`ChordTips.ts`。曲ごとに中身が変わるので `TERMS` ではなく `data-tip` / `data-tip-title` で文を渡す。`Glossary.ts`）。コード名は1つずつ：アルファベットがルート音の名前であること（ドレミの読み）、構成音（今の音名の表記）、後ろの記号（m・7・maj7・sus4 など。`TYPE_TIPS`）の意味と響き、I・IV・V なら役割（家・広がり・家に戻りたくなる）。キーは主音とスケールの説明（`TERMS` の `scale.<スケール>`）。
- 保存・書き出し：「♪ 保存」（ミュージックリスト）は、MIDI・WAV・MP3 の書き出しと同じ「保存・書き出し」の欄に並べる（以前は情報バーにあった。保存＝あとで編集できる、書き出し＝編集し直せないファイル、の違いを下の一言で伝える）。カスタムモードの「♪ 保存」は情報バーのまま。

## カスタムモード

- カスタムモードの「雰囲気」はコード進行の欄の「コード進行の雰囲気」（`#c-mood`。以前の表示名は「カテゴリ」）として選ぶ。スケールは `chordPattern.base_scale` から決まり（別に持たない）、スケールを選ぶとそのスケールのコード進行に切り替わる。スケールの選択肢のうち、ジャンルに合うもの（`genre_scales.json`）には「（おすすめ）」を付ける（ほかのスケールも選べる）。この因果が見えにくいので、切り替わったらスケールの下に「スケールに合わせてコード進行を「…」に変えました」を4秒出し、進行の行を光らせる（`CustomRender.ts` の `notifyChordChange`。`#c-scale-notice`）。
- カスタムモードの設定タブの「もっと調整」（`CustomMore.ts`。`<details class="panel-more" data-more="…">`）：標準（ジャンルに合わせる・初期値）のままでも曲として鳴る項目を各欄の下に畳み、ふだんはジャンル・BPM・小節数・キー・スケール・コード進行・サビ・ドラムだけを見せる。
  - 拍子（`#c-meter`：4/4・3/4・4/4（3連符））は「基本設定」の「もっと調整」で選ぶ。標準はジャンルの拍子（ワルツ = 3/4、6/8バラード・シャッフル = 4/4（3連符）、ほか = 4/4）で、ジャンルを選び直すと、拍子が前のジャンルの標準のままなら新しいジャンルの標準になる。変えるとメロディとオリジナルのドラムを置き直して再生し直す（`setMeter`）。情報バーの拍子（`#c-info-meter`）も変わる。ピアノロールは拍子に合わせて拍・マスの線（`--beats` / `--steps`）を引き、3連符の拍子では音符の長さのボタンが「4分3連」「8分3連」になる。ドラムのロールは DB のパターンを今の拍子のマスに直して見せる。
  - 中身：基本設定 = 拍子・グルーヴ・跳ねる単位（`basic`。メロディの音色は grow の音作りのパネルで選ぶ）、コード進行 = スケールロック・リズム・転調・音色（`chord`）、ドラム = 追加パートを使う・サブベース・FX / SE（`parts`。追加パートは1つでも初期値と違えば1件）。grow の音作りのパネルも同じ形で畳む（`grow`。`GrowPanel.ts` が作る。数は音作りを変えているパートの数）。
  - 見出しに標準から変えている項目の数（「○件変更」／「標準」）を出し、変えている項目の名前（`data-std="…"`。判定は `CHANGED`）の左に印を付ける。「この欄を標準に戻す」でその欄の項目をまとめて戻す（音色が変わるので再生中なら再生し直す。grow は `applyGrowLive()` だけ）。
  - 開閉は端末ごとの表示の設定として localStorage の `toniq.more.<欄>` に保存する（初期は閉じる。`SONG_FIELDS` には入れない）。
  - 印・数は `renderCustomMore()` で更新する（CustomScreen の `render` と GrowPanel の `renderPanel` から呼ぶ）。設定タブに「標準」のある項目を足すときは、名前に `data-std` を付けて `CHANGED` と `resetGroup` に足す。標準のない・よく触る項目は畳まずに外に置く。
- カスタムモードには「生成する」ボタンを置かない（設定の変更はその場で反映され、メロディの作り直しはピアノロールの「自動生成」で行う）。情報バーの主ボタンは「▷ 再生」。
- ミキサー（`MixerPanel.ts`、`#c-arr-mixer`）はアレンジャータブのタイムラインの下にだけ置く（設定タブには置かない）。左端に dB 目盛り、パートごとのチャンネル（色・名前、ON/OFF ボタン（クリックで ON/OFF、右クリックでソロ：`Solo.ts` の `toggleSolo` で、そのパートだけ ON にし、もう一度右クリックすると元の ON/OFF に戻す。ソロ中はボタンにオレンジの枠（`is-solo`）。アレンジャーの右クリック・ピアノロールの「ソロ」と共通）、定位（パン）のノブ `attachKnob`＋値、縦フェーダー `attachFader`＋レベルメーター、値 0〜100）、右端にマスター（クリップの印・左右のメーター・最大のピーク）。フェーダーは `VolumeManager.setVolume` で `AppState.volumes`（初期値は `defaultState.volumes`。曲に保存され、元に戻す／やり直すの対象）を書き換え、Volume ノードにもすぐ当てる。フェーダーの値と dB の換算は `VolumeCurve.ts`（2乗のカーブ `40·log10(値/75)`：75 で 0dB、100 で +5dB、50 で −7dB。目盛りも同じ式から置く。以前は値に比例の `20·log10(値/100)` で、その値で保存した曲（`pans` のない曲）は `loadSong()`（`songFields`）が同じ大きさの値に読み替える `volumeFromLegacy`）。パンのノブは `VolumeManager.setPan` で `AppState.pans`（−100 = 左 〜 0 = 中央 〜 100 = 右。5 刻み。`SONG_FIELDS` に含み、元に戻す／やり直すの対象。初期値はアルペジオ L30・カウンターメロディ R30、ほかは中央）を書き換え、定位のノード（`Tone.Panner`）にもすぐ当てる。ダブルクリックで中央。値は C / L30 / R30（`panLabel`）。パートのメーターは再生中だけ `Tone.Meter`（平均の大きさ。音量・サイドチェイン・パートの EQ・定位のあと）を読む。マスターはリミッターのあとの波形（`Tone.Analyser`。左右）からサンプルのピークを求め（`MixerEngine.getMasterPeaks`）、左右のメーターを別々に動かす。下の数字は再生を始めてからの最大のピーク（dB）で、止めても残す。ピークが `CLIP_DB`（−0.1dBFS）に届くと「CLIP」が赤く点いたまま残る。どちらも次の再生の開始か、CLIP・数字のクリックで消す（表示上の一時的な状態としてモジュール内に持つ）。メーター・波形は WAV / MP3 書き出しのコンテキストには作らない。パートの ON/OFF を1つずつ切り替えるのはアレンジャータブ（ミキサーの ON ボタン・レーンの ON ボタン。どちらも同じ `AppState.parts` を表示する）だけ。設定タブの「もっと調整」の「追加パートを使う」（`#c-extra-parts`）は入り口で、追加パート（`CustomMore.ts` の `EXTRA_PARTS`：パッド／アルペジオ／シグネチャー／カウンターメロディ／パーカッション）をまとめて ON/OFF する（すべて ON ならすべて OFF、一部・すべて OFF ならすべて ON。表示は ON／一部／OFF）。下に今 ON のパートを表示だけで並べ、「パートごとの ON/OFF はアレンジャーで →」でアレンジャータブを開く。
- カスタムモードの設定タブ・アレンジャータブ（`.hw`）と情報バー（`.hw-bar`）とタブ（`.hw-tabs`）はスキンで見た目が変わる。フラットスキンの形はシンセサイザーのプラグイン風（区切り線で仕切ったフラットなグレーの面、白いノブと細い色の弧、下線付きのドロップダウン、グレーの値の箱、情報バー・タブ・小節の目盛りは黒い帯、選択中はオレンジの枠）。色は `--hw-*` / `--knob-*` / `--slider-*` / `--track-*` のトークンを使う。BPM はノブ、コード進行・ドラムパターンは ◀▶ で切り替え（`Controls.ts`）。AppState から range の値を書き換えたら `syncControls()` で見た目をそろえる。
- カスタムモードのスキン（`AppState.skin`。UI 表示名は デフォルト／フラット／スタジオ／ポップ）：
  - `"default"` = メニュー・シンプルモード・ミュージックリストと同じ見た目（初期値）、`"flat"` = フラットなプラグイン風、`"studio"` = 少し暗い制作スタジオ（DAW）風、`"pop"` = クリーム色の地に色分けしたグルーヴボックス風。
  - 選ぶのは設定画面だけ（カスタムモードの情報バーの切り替えボタンは廃止した）。`Theme.ts` が `<html data-skin>` に反映し、localStorage の `toniq.skin` に保存する（`SONG_FIELDS` には入れない。`<head>` でも描画前に付ける）。旧名の `plugin` / `daw` は `flat` / `studio` として読む。
  - `styles.css` の `:root`（ライト）／`:root[data-theme="dark"]` の `--hw-*` などの値と、`.hw …` の無印のスタイルはフラットスキン。ほかのスキンは後ろでトークンと形を上書きする。
  - デフォルトスキンは `:root[data-skin="default"]` でトークンをアプリ共通のトークン（`--surface` / `--border` / `--custom` など）に向けるので、ライト／ダークにそのまま追従する。形（カード・下線のタブ・枠付きのセレクトなど）は `[data-skin="default"] …` で戻す。
  - スタジオスキンは `:root[data-skin="studio"]`（ダークは `:root[data-theme="dark"][data-skin="studio"]`）でトークンを上書きし、形の違い（見出しの帯・箱型のドロップダウン・クリップ風のブロック）だけ `[data-skin="studio"] .hw …` で足す。
  - ポップスキンは `:root[data-skin="pop"]` のトークンに加え、モジュールの色 `--mod`（設定タブの列・アレンジャーごと）とパートの色 `--part`（`--pop-*`。アレンジャーのブロック）で塗り分け、色の上の文字は白にする。
  - トークンを足すときはフラット（ライト／ダーク）・デフォルト・スタジオ・ポップの各スキンに値を入れる。
- ドロップダウン（`<select>`）は `appearance: base-select`（customizable select）でリストをページの中に描く（`styles.css` の末尾）。Electron（Windows）ではネイティブのリスト（OS の別ウィンドウ）が再生の有無に関係なく 30 秒ほど開かないことがあったため（Chrome では起きない）。各スキンの `.hw .select` などが `appearance` を上書きするので、そこだけ `!important`。▾ を背景で描いているセレクトはブラウザの ▾（`::picker-icon`）を消す。リストの色は `::picker(select)` と `option` にトークンで付ける。
- `styles.css` では色を直書きせず、`:root` のトークン（`var(--…)`）を使う。トークンを足すときは `:root[data-theme="dark"]` にもダーク用の値を足す。例外はパートの識別色（`.arr-*` / `.dot-*` のパステル）とアクセント色の上の白文字・クイズの黒鍵で、どちらのテーマでも同じ色を使う。

## ピアノロール・メロディの編集

- ピアノロール（`PianoRollTab.ts`）はコード進行1周分（メロディのループの長さ）を表示し、`AppState.melodyNotes`（サビを選んでいるときは `chorusMelodyNotes`）を直接編集する（鳴る音だけを持ち、休符は持たない）。編集中のセクションは表示上の一時的な状態としてモジュール内に持つ。「自動生成」は Aメロとサビの両方を作り直す。編集すると `melodyMethod` は `"manual"` になり、「自動生成」で `"auto"` に戻る。メロディは単音なので、置いてある音は消さず、ほかの音が鳴っている時刻（同じ時刻を含む）には新しい音を置かない・動かさない（`fitNote`。ピアノロールの下に「ここにはすでに音があります」と数秒出す `showNotice`。鍵盤入力なら入力位置も進めない）。後ろの音にかかる長さは、その手前まで短くする（以前は重なる音を手前で切ったり消したりしていたが、気づかないうちに音が消えるのでやめた）。再生中の編集はメロディだけ読み込み直して（`reloadLayer("melody")`）すぐ反映する。
- メロディは起動時・「＋ 新規作成」では作らず空のまま。自動生成ボタン（ピアノロールの「自動生成」、カスタムモードのメロディの差し替え ↻、シンプルモードで「自動生成」を選んで「生成する」／メロディの「↻ 再抽選」）を押したときに初めて作る。`melodyMethod === "auto"` でも `melodyNotes` が空なら未作成として扱い、コード進行・キーを変えても自動では作らない（作成済みなら作り直す）。
- ピアノロールでメロディを編集している間の再生は、ピアノロールで選んでいるセクション（Aメロ／サビ）の最初の周回だけをくり返す（`sectionRange` を `Playback.setPlayRangeProvider` で渡し、`Playback.play` はその周回の頭から始めて Transport をその範囲でループさせる。セクション・タブを切り替えたら `refreshPlayRange` で当て直し、範囲の外ならその頭へ移る。ピアノロールを離れると、今の位置から曲全体の再生に戻る）。曲にそのセクションの周回がなければ曲全体を鳴らし、そのことを知らせる。ドラムの編集中は曲全体。
- 音符長の選択（ツールバー）のツールチップは `pianoRollLength`（音を置くときに使う長さ。置いたあとは右端のドラッグで16分ずつ変えられる）。選んでいる音符長の名前は音符長のボタンの右に「選択中：4分音符」のように出す。キー・スケール（「Aナチュラルマイナー」などのチップ）は下のステータスバーの左に、Del・鍵盤入力のキーの案内と並べて置く（オクターブの値と「↓↑ オクターブ切替」の案内は消した。オクターブはツールバーの −／＋ と ↓ / ↑ キーで今までどおり変えられる）。
- ピアノロールの入力設定（音符長 `pianoRollLength`・スケールロック `pianoRollScaleLock`・オクターブ `pianoRollOctave`）は AppState に置く。表示の拡大率（横 `pianoRollZoomX`・縦 `pianoRollZoomY`。段は `PianoRollTab.ts` の `ZOOM_X` / `ZOOM_Y`）も AppState に置く（曲には保存しない）。ツールバーの「表示」の − / ＋、Ctrl＋ホイール（横）・Ctrl＋Shift＋ホイール（縦）で変え、マウスの下（ボタンなら見えている範囲の真ん中）が動かないようにスクロールし直す。横はメロディの画面の `--zoom-x`（目盛り・グリッドの幅を鍵盤を除いて倍にし、`.pr-scroll` を横にもスクロールさせる。鍵盤・左上の角は左に固定）、縦は `--row-h`。ドラムのロールは拡大しない。スケールロックはコード進行の `scaleLock` とは別。スケールの7音は `SCALE_TONES`（core＋accent）から作る。選択中の音と鍵盤入力の位置は表示上の一時的な状態としてモジュール内に持つ。
- ピアノロール（メロディ）の左の鍵盤はピアノの形（`PianoRollTab.ts` の `pianoKey`）。黒鍵は自分の行の高さで左から短く重ね、白鍵は隣の黒鍵の行の半分まで伸ばして黒鍵の下に潜らせる（C・E・F・B は 1.5 行、D・G・A は 2 行なので、白鍵の境目は黒鍵の行の真ん中か E/F・B/C の行の境目）。白鍵には自分の行の高さに音名（C はオクターブ付き）、黒鍵にも自分の行に小さく音名（C# など。色は `--key-label-black`）を出す。主音は音名の色（黒鍵は右端の点）、スケールロック中はスケール外の鍵盤を沈ませる。クリック・タイピングピアノで入力すると、その鍵盤が少し光る。色は `--key-*` のトークン（黒鍵はどちらの配色でも同じ）。
- ピアノロールの操作：クリックで配置（そのままドラッグで長さ）、音をドラッグで移動（配置・移動の刻みは選んでいる音符長にかかわらず1マス＝16分音符（3連符の拍子は8分3連符）。`SNAP_UNITS`。音符長は新しく置く音の長さだけに使う）、右端で長さ変更（選んでいる音符長にかかわらず1マス＝16分音符（3連符の拍子は8分3連符）ずつ。後ろの音の手前まで）、右クリック／Delete で削除、目盛りクリックで鍵盤入力の位置、タイピングピアノで鍵盤入力（`TypingKeys.ts` の `TYPING_KEYMAP`。キーの物理的な位置 `KeyboardEvent.code` で決める。Z〜/ の段が基準のオクターブの C〜1オクターブ上の E で S D G H J L ; が黒鍵、Q〜] の段が1オクターブ上の C〜2オクターブ上の G で 2 3 5 6 7 9 0 = が黒鍵。基準のオクターブ `pianoRollOctave` は 3〜5、初期値 4 で C4〜G6。C7 より上は置かない）、↓ / ↑ でオクターブ切替、スペースキーで再生／停止（曲の先頭から。`SpaceKey.ts`。docs/arrangement.md）。
- ピアノロールのソロ：メロディ・ドラムの両方のツールバーで「メロディ／ドラム」の横に「ソロ」ボタン（`data-pr-solo`）を置き、編集中のパートだけ ON にしてほかを OFF にする。もう一度押すとソロにする前の ON/OFF に戻す。ソロの処理はアレンジャーの ON/OFF ボタンの右クリックと共通（`Solo.ts` の `toggleSolo` / `soloPart`。docs/arrangement.md）で、編集中のパートのソロ中ならボタンを点ける。
- ピアノロールのドラム（`DrumRoll.ts`）：ツールバー先頭の「メロディ／ドラム」で切り替える（どちらを表示中かは表示上の一時的な状態として `PianoRollTab.ts` に持つ。鍵盤入力などのキー操作はメロディのときだけ）。行 = ドラムのトラック（上からオープンハイハット・クローズドハイハット・クラップ・リム・スネア・キック。`DRUM_ROLL_TRACKS`）、列 = 16分音符のマス。クリックで置く・消す（押したマスが空いていれば置く、あれば消す。そのままドラッグで同じ操作をまとめて）、右クリック（ドラッグ）で消す、行の見出しで試聴（`previewDrumHit`）。置く強さ（強 1・中 0.75・弱 0.45）は `AppState.drumRollVelocity`（曲には保存しない）。長さは 1・2・4 小節（`CUSTOM_DRUM_BARS`。長くするときは繰り返し、短くするときは切る）。「パターンを読み込む…」で DB のパターンに戻し、「クリア」で空にする。
  - 編集すると `AppState.drumPattern` が DB にないオリジナルのパターン（`id` = `CUSTOM_DRUM_ID`（`"custom"`）、`name` = 「オリジナル」、`notes` にもとにしたパターン。`customDrumPattern` / `withDrumHit`）になり、曲と一緒に保存される（`SONG_FIELDS` の `drumPattern` そのまま）。ドラッグ中は画面だけ描き直し、離したときに1回だけ `setState` する（元に戻すも1回で戻る）。再生中のドラムは発音のたびに今の `drumPattern` を読むので、読み込み直さなくてもすぐ反映される。
  - 複数小節のパターンは、曲の小節 `bar` から `(bar * 16 + step) % steps` で位置を決める（`drumStepHits`。DB の1小節のパターンは今までどおり）。アレンジャーでセクションに別のパターンを選んだ所はそちらが鳴る（ステータスバーに注意を出す）。設定のフィル（`drumFill`）・エンディング（`endingEnabled`）が ON なら、その小節は作ったドラムの代わりにフィル・エンディングの音が鳴るので、競合する可能性があることをステータスバーに出す（両方 OFF なら出さない）。カスタムモードのドラムの絞り込みを変えても、オリジナルのパターンは置き換えない。表示名は設定タブ「オリジナル（ピアノロールで作成）」、アレンジャー「オリジナル」。

## ミュージックリスト・曲ファイル・出力

- ミュージックリスト（`SongLibrary.ts`）は曲の内容（`SONG_FIELDS`：モード・ジャンル・キー・BPM・小節数・パターン・メロディ・音色・アレンジ・パートON/OFF・音量）を localStorage に保存する。画面・タブ・ピアノロールの入力設定は保存しない。曲の内容に関わる項目を AppState に足したら `SONG_FIELDS`（`AppState.ts` に定義）にも足す。`SONG_FIELDS` は曲ファイルと元に戻す／やり直すの対象にもなる。
  - localStorage に書き込めない（容量オーバーなど）と `writeSongs` が `SongStorageError`（`quota` = 容量オーバーか）を投げ、一覧は書き込む前のまま残る（`saveCurrentSong` は `songId` も変えない）。画面側（`SongSave.ts`。`MusicListScreen.ts`・`ExportProgress.ts` から使う）は `saveToList`（「♪ 保存」。編集中の曲は消えないので、整理してから保存し直すよう知らせる）と `withStorage`（名前の変更・お気に入り・削除）で受けて知らせる。曲ファイルの読み込みは今までどおりファイルごとのエラーとして出す。ミュージックリストを書き換える操作を足すときも、どちらかで囲む。
- 曲ファイル：書き出し（「すべて書き出す」・⋮ メニューの「曲ファイルに書き出す」）と「ファイルを読み込む」のボタンは廃止した（`importSongFile` はテストのために残している）。形式は `{ format: "toniq-song", version, exportedAt, songs: SavedSong[] }` の JSON（拡張子 `.toniq.json`）。読み込んだ曲は新しい ID で一覧に追加する（上書きしない）。コード進行・ドラムなど鳴らすのに必要な項目がない曲は飛ばし、足りない項目は `loadSong()` と同じく初期値で補う。そのあと `validateImportedSong()`（`SongValidate.ts`）で中身を確かめ、鳴らすときに例外になる曲（知らないキー・ディグリー・コードの種類・スケール）は飛ばし、形の違うメロディの音・ドラムのトラックは落とし、範囲外の値は直す。形式を変えるときは `FILE_VERSION` を上げ、古い形式も読めるようにする。
- 作業ファイル（今の曲1曲分を .toniq.json に保存・開く機能。情報バーの「⇩ 作業ファイル」・メニューの「作業ファイルを開く」・`AppState.projectPath`・`output/projects`）は、ミュージックリストへの保存とほぼ同じなので廃止した。（曲ファイルの書き出し・読み込みのボタンもあとで廃止した。）
- 出力フォルダ：
  - Electron では WAV / MP3 / MIDI を、書き出す前に `askExportFile()`（`FileNameDialog.ts`。Electron では `prompt()` が使えないので自前のダイアログ）でファイル名を決め、`saveOutput()`（`OutputFiles.ts`）で `output/audio` / `output/midi` に直接保存し（同名なら「 (2)」を付けて上書きしない）、保存後にフォルダを開くか聞く。
  - 書き出す前の注意（`ExportProgress.ts` の `prepareExport`）：ファイル名のダイアログに「書き出したファイルは Toniq に読み込んで編集し直せない（MIDI はほかの作曲ソフトでは編集できる）」と書く。保存していない変更がある曲（`hasUnsavedSong`）なら「ミュージックリストにも保存する」のチェック（初めから ON）を出し、入れたまま書き出すと先に保存する。初めて保存する曲は、リストの曲名を書き出すファイル名にそろえる。保存できなければ書き出しもやめる。
  - 書き出しの中断：進み具合のダイアログの「中断する」（Esc でも）で、`AbortController` の signal を `Playback.renderAudio` に渡して止める（何も保存しない）。演奏の予定の組み立て中は Tone.js の `OfflineContext` の残りの長さ（内部の `_duration`）を負にしてループを抜けさせ、音声の合成中は次の一時停止（`suspend`）から再開しない。MP3 の変換は区切りごとに確かめる。どれも `RenderCancelled` を投げ、`renderSong` は描き直しをせず書き出し用の Synth を捨てる。予備の `Tone.Offline` で描き直している間は止められないので、終わってから捨てる。
  - 出力フォルダの場所は開発時が toniq フォルダの `output/`、インストール版は Toniq.exe と同じ場所の `output/`（書き込めなければ「ドキュメント/Toniq/output」）。起動時に作る。 ミュージックリストの「出力フォルダを表示」ボタン（`MusicListScreen.ts`）で開く。
  - ブラウザで開いたとき（`window.toniqFiles` がない）は、書き出しはダウンロードになり、「出力フォルダを表示」ボタンは隠す（保存した曲の表示では欄 `#ml-files-bar` ごと隠す）。
- `AppState.songId` は今の曲がリストのどの曲か（`null` = 未保存）。リストから開いた・保存した曲は「上書き保存」になり、シンプルモードで生成し直すと `null` に戻って新しい曲として保存される。リストで再生・開くと、その曲を今の曲として読み込む（保存していない変更があれば確認する。下の「保存していない変更」）。 ミュージックリストの曲の行には「編集」ボタン（`data-action="open"`。曲のモードで開く）を出す（以前は ⋮ メニューの中にあって気づきにくかったため。曲名のダブルクリックでも開く）。⋮ メニューは名前の変更・WAV / MP3 / MIDI で書き出す（その曲を今の曲として読み込んでから、両モードと同じ手順で書き出す `exportSongAs`）・曲ファイルに書き出す（以前の表示名は「ファイルに書き出す」。WAV などと区別するため変えた）・削除。
- 保存していない変更（`SongLibrary.ts` の `hasUnsavedChanges`）：保存・読み込み（`loadSong`）・新規作成（`newSong`）・起動のときに曲の内容（`SONG_FIELDS`。モードは除く。キーの順は問わない）を基準として記録し（`markSongClean`）、今の内容と比べる。リストから今の曲を消すと基準をなくす（変えていなくても変更あり）。シンプルモードの生成前は、ピアノロールで作った内容（手入力のメロディ・オリジナルのドラム。`hasHandmadeContent`）があるときだけ変更ありにする。サンプルの試聴・メロディの評価で一時的に差し替えているときは、差し替える前の内容（`Playback.sampleOriginal()`・`songBeforeRating()`）で比べる（`SongSave.ts` の `hasUnsavedSong`。ミュージックリスト・新規作成・書き出しのダイアログで共通）。
  - 変更があるときだけ、別の曲を開く・ウィンドウを閉じる（読み込み直す）前に確かめる（「＋ 新規作成」は下のとおりいつも確かめる）。閉じるときは `beforeunload` で止め、ブラウザは標準の確認、Electron は `will-prevent-unload`（`electron/main.ts`）で「保存せずに閉じる／キャンセル」のダイアログを出す。開発時の Vite の読み込み直しでも出る。
- 両モードの情報バーの「＋ 新規作成」は、実行する前にいつもダイアログ（`ChoiceDialog.ts` の `askChoice`。`MusicListScreen.ts` の `confirmNewSong`）で、今の曲の編集内容が消えて設定が初めの状態に戻ることを知らせる。保存していない変更があれば「保存せずに新規作成」「（上書き）保存してから新規作成」「キャンセル」、なければ「新規作成」「キャンセル」（リストにある曲なら、あとでリストから続きを編集できることを添える）。確かめたあと再生を止めて `newSong()`（`SongLibrary.ts`）で曲の内容（`SONG_FIELDS`）を `defaultState` に戻し、`songId` を `null` にする。モードはそのまま、シンプルモードは設定画面（`generated: false`）に戻る。パターンは起動時と同じく初期のジャンル・雰囲気で決め直す（メロディは空にする）。
- ミュージックリストの絞り込み・並び順（`musicListQuery` / `musicListGenre` / `musicListFavorites` / `musicListSort`）は AppState に置く。⋮ メニューを開いている曲・名前を変更中の曲は表示上の一時的な状態としてモジュール内に持つ。お気に入りは曲データ（`SavedSong.favorite`）に保存する。
- ミュージックリストの上の大きなタブで「保存した曲」（Toniq で続きを編集できる）と「書き出したファイル」（WAV・MP3・MIDI）を切り替える（`AppState.musicListView`。保存しない表示の状態）。
- 書き出したファイル（`OutputFileList.ts`）：`output/audio`・`output/midi` の直下の `.wav` / `.mp3` / `.mid` / `.midi` を一覧にする（Electron の `toniq:list-output-files`。preload の `listOutputFiles`）。種類のチップ（すべて／WAV／MP3／MIDI。数を添え、0 個の種類は押せない。`AppState.musicListFileType`）で絞り込み、並び順は曲と同じ `musicListSort`（更新日時・名前）。行は種類の印・大きさ・更新日時・「場所を開く」（エクスプローラーで表示）・ごみ箱へ移す（`shell.trashItem`。元に戻せる）。WAV・MP3 は ▷ で聴ける（`toniq:read-output-file` で中身を読んで Blob の URL を `<audio>` で鳴らす。曲の再生（Tone.js）とは重ねない：鳴らすと曲を止め、曲を鳴らす・表示を切り替える・画面を離れるとファイルを止める）。MIDI は再生しない（DAW などで使う）。一覧は画面に入ったとき・表示を切り替えたとき・リストから書き出したあと・「↻ 更新」で読み直す。メインプロセスは渡されたパスが `output/audio`・`output/midi` の直下のその拡張子のファイルかを確かめてから読む・ごみ箱へ移す。ブラウザでは書き出しがダウンロードになるので、一覧の代わりにその案内を出す。
- ミュージックリストの画面の並び（`index.html` の `data-screen="musiclist"`。「保存した曲」のとき）：
  - 上に小さく右寄せで曲ファイルの操作（`.ml-files`：「出力フォルダを表示」。Electron のときだけ）、その下に絞り込みのツールバー（検索・並び順のドロップダウン `#ml-sort`（新しい順／古い順／名前順）・お気に入り）、ジャンルのチップ、曲の一覧。役割の違うボタンが1列に混ざらないように分けている。ツールバーのボタンは縮めず文字を折り返さない（幅が足りなければボタンごと次の行へ送る）。
  - 検索（`matchesQuery`）は曲名・ジャンル・雰囲気・キー（「A ナチュラルマイナー」のようにキー＋スケール名）から探す。大文字・小文字は区別せず、スペース（全角も）で区切った言葉はすべて含む曲に絞る（例：「EDM 明るい」）。
  - ジャンルのチップには、検索・お気に入りの条件に合う曲の数を添える（「すべて」は合う曲の合計）。0 曲のジャンルは押せなくして薄く表示する（押してから「条件に合う曲がありません」と出る空振りを防ぐ）。選んでいるジャンルは 0 曲でも押せるまま。
  - 曲の行は、曲名の下にジャンル・雰囲気・キー・BPM を小さく出す（似た名前の曲を見分けられるように）。小節数とモードは曲名のツールチップに出す。長さは拍子（`meter`。ない古い曲は 4/4）の1小節の拍数で計算する。

## 元に戻す／やり直す

- 元に戻す／やり直す（`History.ts`）：`setState` の直前（`onBeforeSetState`）に、`SONG_FIELDS`（モードを除く）が変わるなら変更前のスナップショットを積む（最大100）。押してから離すまで（ドラッグ・ノブ）と、操作が途切れるまで（600ms）の変更は1つにまとめる。シンプルモード・カスタムモードの画面でだけ使え、文字の入力欄ではブラウザ標準の元に戻すになる。
  - 表示用の一時的な差し替え（ジャンルのサンプル試聴など）は `withoutHistory()` で囲んで履歴に残さない。描画関数の中で曲の内容を `setState` しない（やり直しの履歴が消える）。
  - 曲を開いた（`loadSong`）・新規作成（`newSong`）・シンプルモードの「生成する」（新しい曲になる）・起動時は履歴を捨てる（`resetHistory`。前の曲の内容に戻せないようにする）。
  - 戻したとき再生中なら、アレンジ・音量・パートON/OFF・メロディだけの変更はその場で反映し、それ以外は各画面の `restartIfPlaying()` で再生し直す。

## 設定画面・端末ごとの設定

- 設定画面（`SettingsScreen.ts`、`data-screen="settings"`）はメニューの横長の「設定」カードから開く。端末ごとの設定（配色・スキン・音名の表記・ループ再生・ドラムの音源・ツールチップ）を集める。曲に保存する項目は置かない。設定を足すときは AppState に項目を足し、保存は担当のモジュールが localStorage（`toniq.*`）に行い、表示の切り替えは `<html data-*>` で行う。
  - 最後の「ヘルプ」欄（`index.html` の `.settings-help`。`<details>` の開閉式で、JS はなし）に、見ただけではわかりにくい操作（ピアノロール・アレンジャーのマウス・キー操作、ノブの Shift・ホイール、タップテンポ、元に戻すのショートカット、保存の種類、試聴、テスト中の機能）を書いている。操作を足す・変えたらここも直す。
- 配色は選び方を `AppState.themeMode`（`light` / `dark` / `system` = OS に合わせる）、実際の配色を `AppState.theme` に置き、`Theme.ts` が `<html data-theme>` に反映して localStorage の `toniq.theme` に保存する（未保存か `system` なら OS の設定に合わせ、OS の配色が変わったら追従する。配色は設定画面だけで選ぶ（ヘッダーの切り替えボタンは廃止した）。曲の内容ではないので `SONG_FIELDS` には入れない）。`index.html` の `<head>` でも同じキーを読んで描画前に `data-theme` を付ける。
- 音名の表記（`AppState.noteNames`：`cde` / `doremi`。初期値は `doremi`。`cde` を保存した端末はそのまま）はアプリ全体の設定。設定画面と音楽クイズのツールバーのどちらでも切り替えられ、`Preferences.ts` が `toniq.noteNames` に保存する。表示は `format.ts` の `displayNote`（`"C#4"` のようなオクターブ付きも可）で変える。単音（ピアノロールの鍵盤・音符、クイズの単音・構成音）だけを変え、コード名・キー名は CDE 表記のまま（カスタムモードのルート音の選択肢は、ドレミ表記なら `A（ラ）` のように読みを添える）。
- 用語のツールチップ（`Glossary.ts`）：要素に `data-term="キー"` を付けると、カーソルを乗せる（キーボードならフォーカスする）と少し待って `TERMS` の説明を出す。`span` とアレンジャーのレーン名には点線の下線が付く。パート名（`LayerName`）はそのまま `TERMS` のキーとして使う（アレンジャー）。説明は初心者向けに1〜2文で、専門用語を重ねない。新しい用語を画面に出したら `TERMS` に足して `data-term` を付ける。
  - ドロップダウンの選択肢（`<option>`）にも `data-term` を付けられる（キーは `scale.<スケール>`・`chordRhythm.<リズム>`・`fx.<種類>`・`sound.<grow のプリセット ID>` の形）。リストの項目にカーソルを乗せる（キーボードで選ぶ）とリストの横に出す。リストはトップレイヤーに描かれるので、ツールチップは popover（`popover="manual"`）で出し直して上に重ねる。`TERMS` にないキーの選択肢は何も出さない。grow の音作りのパネルのプリセットのチップ（`sound.<ID>`）と行の名前（`growCategory.<カテゴリ>`・`growCategory.standard` / `other`）にも同じ説明を出す。パネルに出るプリセット・カテゴリにはすべて説明を書く（足し忘れは `tests/GrowPresets.test.ts` で落ちる。ドラム・パーカッションのプリセットはパネルに出ないので不要）。
  - ON/OFF は設定画面で切り替える（`AppState.tooltips`、localStorage の `toniq.tooltips` = `on` / `off`、`<html data-tooltips>`。OFF では下線も出さない）。`<head>` でも描画前に `data-tooltips` を付ける。曲の内容ではないので `SONG_FIELDS` には入れない。

## メロディの評価（開発用）

- 生成ルールの良しあしを、自動チェック（`npm run quality`）ではなく人が聴いて確かめる画面（`RatingScreen.ts`、`data-screen="rating"`）。設定画面の「開発用」の「評価を始める」から開く（メニューには出さない）。
- 曲は一括計測と同じ手順・同じシードで作る（`QualityBatch.ts` の `generateBatchSong(seed, genre, mood, run)`。キーは 12 のキーを順に）。ジャンル×雰囲気を `easy_mode_table.json` の順に回し、1周ごとに番号 `run` を進めるので、No.n の曲は `npm run quality` の同じシード・同じ番号の曲と同じになる。
- 使い方：生成ルールを変える前に条件名を「変更前」にして聴き、変えたあと「変更後」にして同じ番号の曲を聴く。「同じ曲で比べる」で、両方の条件で聴いた曲どうしの点数の差（上がった・下がった・同じの数、メロディが変わらなかった曲の数）を出す。結果の表は条件ごとの平均・分布・自動チェックが全合格の曲と不合格ありの曲の平均・多かったタグと、ジャンルごとの平均。
- 点数は 1〜5（悪い／いまいち／ふつう／良い／とても良い）。任意でタグ（`RATING_TAGS`：覚えやすい・流れが自然・単調・跳びすぎ・山がない・リズムが不自然・終わり方が不自然・サビが弱い）とメモを付ける。点数を押すと保存して、今の条件でまだ付けていない次の曲へ進む（再生中なら続けて鳴らす）。同じ条件・同じ曲は付け直しになる。自動チェックの結果は先入観にならないよう、点数を付けたあとに出す。
- 鳴らすパートは「全パート／メロディ＋コード＋ベース／メロディだけ」。「サビから」は最初のサビの小節から鳴らす。キー操作：`1`〜`5` 点数、Space 再生／停止、`C` サビから、`←` `→` 前後の曲。
- 聴いている間だけ AppState の曲の内容（`SONG_FIELDS`）を差し替え、画面を離れると入る前の曲に戻す（`Router.ts` の `onScreenChange`。元に戻す／やり直すの履歴にも残さない）。
- 評価は `MelodyRatings.ts` が localStorage の `toniq.ratings` に保存する（曲には保存しない）。条件名・シード・絞り込み・鳴らすパートは `toniq.ratings.settings`。CSV（Excel 用に BOM 付き）・JSON に書き出せ（Electron は `output/quality`）、JSON は読み込んで足せる（同じ条件・同じ曲は読み込んだほうで置き換える）。条件ごとに消せる。
- 生成ルールで `Math.random` を呼ぶ回数が変わると、同じ番号でも曲（コード進行・キー以外）が変わることがある。比べるのは「同じシード・番号から作った曲」で、まったく同じ伴奏とは限らない。

## 試聴

- BPM の試聴（`Metronome.ts`。シンプルモードの「♪ テンポを聴く」（以前は「♪ メトロノームで速さを聴く」。テンポ欄の「ゆっくり／普通／速い」は丸いチップ、「☝ タップで調整」「♪ テンポを聴く」は区切り線の右に角の丸い四角（`.tempo-tool`）で置き、選択肢と道具を見分けられるようにする）、カスタムモードの BPM ノブ横の「♪ メトロノーム」。初心者には「クリック」が拍の音のことだと伝わらないので、メトロノームと書いて用語の説明 `metronome` を付ける）は、曲の再生（Tone.js）とは別のオーディオコンテキストで 4/4 のクリック音（1拍目は高い音）を鳴らす。拍ごとに `AppState.bpm` を読むので、鳴らしたまま BPM を変えるとすぐ反映される。鳴っているかどうかは表示上の一時的な状態としてモジュール内に持つ（保存しない）。曲の再生・試聴の開始、画面の切り替え、シンプルモードの生成で止める。
- キー・スケールの試聴（`ScalePreview.ts`。カスタムモードの「スケール・キー」欄の「響き」の「▷ 試聴」）は、今のキー（`AppState.key`）とスケール（`chordPattern.base_scale`）で、主音から1オクターブ上までの音（ふつうは8音。メジャーペンタトニックは6音・全音音階は7音。主音は A3〜G#4）を順に鳴らし、最後に主音の和音を鳴らす。スケールの7音は `scaleSemitones()`（`degree_resolver.ts`。`SCALE_TONES` から作る。ピアノロールのスケールロックと共通）。曲の再生とは別のオーディオコンテキストで鳴らし、欄に並べた音名（`displayNote` で今の表記）のうち鳴っている音を光らせる。鳴っている・何音目かは表示上の一時的な状態としてモジュール内に持つ。鳴らしたままキー・スケールを変えると鳴らし直す。曲の再生・試聴・サンプルの開始、BPM のクリック音、画面の切り替えで止める。
- grow の音色の試聴（`GrowPreview.ts`）：カスタムモードのコードの音色、grow の音作りのパネルのプリセット（チップの一覧。選んでいるチップをもう一度押したときも鳴らす）を選び直すと、そのパートの今の音作り（プリセット＋変えた値）で曲のキーの主音を1音鳴らす（ベースのカテゴリは A1〜G#2、それ以外は A3〜G#4）。長さはプリセットのカテゴリで変える（パッド・質感 2.5 秒、FX 2 秒、ほかは 1 秒。`NOTE_SECONDS`）。曲の再生中は鳴らさない（変更が再生中のパートにそのまま反映されるため）。曲の再生（Tone.js）と同じコンテキストで、ミキサーを通さず出力へつなぐ。次の試聴、曲の再生・試聴・サンプルの開始（`Playback.ts`）で前の音を短くフェードして止める。鳴っている音は表示上の一時的な状態としてモジュール内に持つ。
- grow の試し弾き（`GrowPanel.ts` のキー操作 → `GrowPreview.ts` の `growKeyDown` / `growKeyUp`）：カスタムモードの設定タブ・アレンジャータブで、ピアノロールと同じタイピングピアノのキー（`TypingKeys.ts` の `TYPING_KEYMAP`）を押している間、音作りのパネルの「対象」のパートの今の音色（プリセット＋つまみ。つまみを動かすと鳴らしたまま変わる）を鳴らす。ピアノロールのタブでは同じキーがメロディの入力になるので鳴らさない。基準のオクターブは「対象」のパートごとに表示上の一時的な状態として持ち（ベースは 2、それ以外は 4 から。1〜6）、↓ / ↑ で切り替える（つまみ・スライダーにフォーカスがあるときは矢印はその値の変更）。曲の再生中も鳴らせる（ミキサーを通さず出力へつなぐ）。対象の切り替え・ほかのタブや画面への移動・ウィンドウを離れたときは鳴っている音を止める。パネル上部に今のオクターブの案内を出す。

## 音楽クイズ

- 音楽クイズは初心者向け。カテゴリは「音の高さ」「コード・スケール」「リズム・音響」「用語」の4つで、各カテゴリの中はやさしい順に並べる。上級者向けの内容（テンション・転回形・ミックスの聴き分けなど）は足さない。聴き取り・知識の難しいモードは、出題範囲の初期値をやさしいものに絞り（`QuizCore.ts` の `startWith`）、出題設定の `hint` で「慣れたら増やす」と案内する。
- 音楽クイズ：選んでいる出題モード（`quizMode`）は AppState に置く。出題中の問題・成績（正解数・連続）は表示上の一時的な状態として `QuizScreen.ts` に、出題設定は各モード（`modes/` の各ファイル）に持つ（どちらも保存しない）。モードを足すときは `QuizMode`（`settings` と `question()`、必要なら出題設定に出すおすすめ `hint`）をカテゴリの `src/quiz/modes/*.ts` に作り（共通のデータ・ヘルパーは `QuizCore.ts`）、`QuizModes.ts` の `QUIZ_CATEGORIES` に加える。問題は回答方法（`choice` 選択肢／`notes` 鍵盤で複数選択／`key` 鍵盤を1つ押す）、回答後の一言の解説（`explain`）、再生ボタン（`sounds`、`afterAnswer` で回答後だけ表示）で表す。
- クイズの音名の表記：単音・構成音は `displayNote`（`format.ts`。`QuizCore.ts` / `QuizModes.ts` から再エクスポート）で今の表記にする。コード名・キー名は CDE 表記のまま。`notes` / `key` の正解は CDE 表記（`NOTES`）で持ち、表示するときに変換する。表記を切り替えると新しい問題を出す。
- 音程を鍵盤で答える問題（音程聴音・「音程（度数）」の鍵盤で回答）は、音名ではなく鍵盤の位置（`QuizKeyAt`）で判定する。2オクターブの鍵盤の左のオクターブに1音目を置き、答えはいつもそれより右（P1 は1音目と同じ鍵盤、P8 は1オクターブ上）。「2音間の音程」の参照用の鍵盤も2オクターブで、2音目を1音目より右に出す。
- 周波数帯域の音は、ピンクノイズ（1オクターブあたりの強さが同じ）を Q 1.1 のバンドパスで切り出す（`playBandNoise`）。ホワイトノイズだと高い帯域ほど大きく鳴り（40Hz と 14kHz で約 20dB の差）、大きさで答えがわかってしまうため。耳の感度が低いサブベース（+4dB）と、ナイキスト周波数の近くで帯域が欠ける超高域（+2.5dB）だけ `EQ_BANDS` の `trim` で持ち上げる。
- クイズの音は曲の再生（Tone.js）とは別のオーディオコンテキストで鳴らす。新しい音を鳴らす・次の問題へ進む・画面を離れると前の音を止める。クイズ画面に入ると曲の再生は止める。

## 画面の移動

- パンくず（`Router.ts` の `crumbsFor` / `renderBreadcrumb`。メニュー以外のすべての画面の上部）は、今いる場所を「‹ メニューに戻る › シンプルモード › 生成した曲 › ピアノロール」のようにたどる。先頭の「‹ メニューに戻る」（枠付き）がメニューへの導線で、途中の段（シンプルモード・カスタムモード＝設定タブ、生成した曲、設定（メロディの評価から））は押すとその画面・タブへ移る。最後の段は今いる場所で押せない。シンプルモードは生成前が「設定」・生成後が「生成した曲」、カスタムモードはタブ名、ミュージックリストは「保存した曲／書き出したファイル」。画面の切り替え（`Router.render`）に加え、シンプルモード・ミュージックリストの描画でも描き直す（生成・表示の切り替えで段が変わる）。ヘッダーの「⋯」メニューとシンプル／カスタムの切り替えボタンは廃止した。
  - シンプルモード（生成後）・カスタムモードで「‹ メニューに戻る」を押したとき、保存していない変更があれば「楽曲を保存しますか？」のダイアログ（`askChoice`。「保存して戻る」（リストにある曲は「上書き保存して戻る」）／「保存せずに戻る」／キャンセル）を出す（`MusicListScreen.ts` の `confirmBackToMenu` を `Router.setMenuGuard` で登録する）。メニューに戻るだけでは曲は消えないので、保存せずに戻ることもできる。
- 画面を移ると（`showScreen`。メニューに戻る・ピアノロールからほかの画面へ移るなど）、曲を再生中なら止める。
- 停止ボタン（シンプルモードの `data-simple-stop`・カスタムモードの `#c-stop`。`.btn-stop`）は鳴っている間だけ出し、再生ボタンと見分けやすいよう赤系（`--danger-*`）で「■ 停止」と書く。
