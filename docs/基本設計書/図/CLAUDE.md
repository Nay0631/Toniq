## 設計書の図（PlantUML）

- 図は `docs/基本設計書/図/<図の種類>/` に PlantUML（`.puml`、UTF-8）で書き、同じ名前の `.svg` を同じフォルダに出力する。PNG は使わない。
- 図は仕様書（`docs/基本設計書/仕様書.md`）をもとに描く。コードから直接描かない。機能ID・機能名・日本語の名前は仕様書の機能一覧と名前の対応表に合わせる。
- ファイル名（＝図名）は機能IDで始める。機能の数が変わっても付け直さずに済むよう、機能一覧の No は使わない。
  - ユースケース図: `<グループID>_<システム名>_ユースケース図`（例: `B01_基本設定システム_ユースケース図`）。システム名は仕様書 5.1 の表の1行目（`**B01_基本設定システム**`）の名前。全体の図（`全体_楽曲生成システムToniq_ユースケース図`）は作らない（2026-11-16 決定。ファイルは残っているが更新しない）。仕様書・docx の見出しには「_ユースケース図」を付けない（`B01_基本設定システム`）
  - ロバストネス図・シーケンス図・クラス図: `<機能ID>_<機能名>機能_<図の種類>`（例: `B01-1_BPM選択機能_ロバストネス図`。機能名は仕様書の機能一覧の名前）。クラスの全体図（`全体_クラス図`）は作らない（2026-11-16 決定。ファイルは残っているが更新しない）
- `.puml` を追加・修正したら、対応する `.svg` も作り直す。変換後に `.svg` の中を「Syntax Error」で検索して、エラーが無いことを確かめる。
- 見た目は astah 風にそろえる。`@startuml` の直後で、図の種類ごとの共通設定を `!include` する。図の中に `skinparam` を書かない。
  - ユースケース図: `!include ../astah-usecase-style.puml`、枠は `mainframe **uc** <図名>`
  - ロバストネス図: `!include ../astah-robustness-style.puml`、枠は `mainframe **uc** <図名>`
  - シーケンス図: `!include ../astah-sequence-style.puml`、枠は `mainframe sd <図名>`
  - クラス図: `!include ../astah-class-style.puml`、枠は `mainframe **pkg**`
  - 画面遷移図: `!include ../astah-state-style.puml`、枠は `mainframe **stm** <図名>`
  - システム概要図・システム構成図: `!include ../astah-system-style.puml`、枠は `mainframe **deployment** <図名>`（並べる向き `left to right direction` / `top to bottom direction` は図ごとに書く）
- `title` は使わない（枠に図名を入れる）。
- 共通設定ファイル（`astah-*.puml`）には `@startuml` / `@enduml` を書かない。
- 名前は日本語で書く。画面・処理・データ・クラス・操作・属性に、コードの識別子（`SimpleScreen`、`setState()` など）は使わず、日本語の名詞・動詞にする（例: 「シンプルモード画面」「コード進行を再抽選する()」「コード進行マスタ」）。同じものはどの図でも同じ名前にする。
- 細かさは利用者の操作の単位にそろえる。画面の描き直し・状態の読み書きなど、画面の中の細かい呼び出しは書かない。
- ユースケース図: 利用者は `actor "利用者" as A1`。利用者とユースケースは `A1 -- UC1`（矢印なし）でつなぐ。
  - システム名は境界（システムの範囲の四角）の外側の上に出す。名前だけの外側の四角（ステレオタイプ `<<システム名>>`。枠線なし・共通設定で定義）の中に、名前なしの境界の四角を入れる：
    ```
    rectangle "基本設定システム" <<システム名>> {
      rectangle " " {
        usecase "BPM選択機能" as UC1
      }
    }
    ```
  - グループの図のシステム名は、そのグループのシステム名（仕様書 5.1）。
- ロバストネス図: `actor` / `boundary`（画面）/ `control`（処理）/ `entity`（データ）を使う。線は向きのある矢印 `-->` で書き、線には操作や条件を書く（例: `A1 --> B1 : 生成するボタンを押下する`）。
  - つないでよいのは、利用者 → 画面、画面 → 処理、処理 → 処理、処理 → データ、処理 → 画面（処理の結果として別の画面へ移る・画面に表示する）。利用者 → 処理・データ、画面 → 画面、画面 → データはつながない（間に処理を置く）。
  - 入力が足りないなどで先へ進めないときは、処理の自己ループで書く（例: `C1 --> C1 : ファイルが選択されていない`）。
  - 自己ループは、先へ進めない・取り消される条件と、その処理の中だけで終わる短い動きにだけ使い、1つの処理に1本までにする。合成・変換などの処理の手順は自己ループにせず、別の処理（control）として描く（例: A01-5 の「音声合成」「音声変換」。名前は仕様書の付録A に足し、シーケンス図・クラス図もそろえる）。
  - 自己ループのラベルは横に長いとほかの線のラベルに重なるので、13文字くらいで `\n` で改行する（「（」の前、「、」の後、助詞の後で切る。英単語の途中では切らない）。例: `C1 --> C1 : 未保存の曲を\n捨てる確認で取り消した\n（開かない）`
  - 線の文（ラベル）は、どの矢印の文か分かるよう、その矢印のすぐ上に矢印と平行に置く。PlantUML ではそう置けないので、SVG に変換したあと `node docs/基本設計書/tools/robustness_labels.mjs`（リポジトリのルートで。ロバストネス図のフォルダの SVG をすべて処理し、処理済みの SVG は変えない）で置き直す。スクリプトは線に沿って、ほかの文・線・アイコンと重ならない位置を選び、文を線より手前に白い下地付きで描く（2026-11-12 決定）。
    - 置き直した SVG は手で直さない。文の位置を変えたいときは .puml（ラベルの文・改行）を直して変換し直し、スクリプトをもう一度動かす。
    - スクリプトが「重なり N 件」と出した図は、ラベルを短くする・`\n` で改行するなどして .puml を直す。
    - 自己ループの文は PlantUML の位置（ループの上）のまま。ほかの線に横切られるときだけ、ループの近くで少しずらす。
  - 置き直したら、文字どうし・文字と線が重なっていないか画像で確かめる（Edge か Chrome のヘッドレスで SVG を PNG にして見る。`robustness_labels.mjs <SVG> --png <フォルダ>` で作れる）。
- シーケンス図: 参加者の表示名は先頭に「:」を付ける（`actor ":利用者" as L1`、`boundary ":シンプルモード画面" as L2`）。メッセージ名は `操作名() : void` の形にする（例: `L1 -> L2 : 再生ボタンを押下する() : void`）。メッセージを受け取った側を `activate` / `deactivate` する。`alt` などの分岐の中で `activate` したものは、その分岐の中で `deactivate` する。
- クラス図: `class "クラス名" as C1 <<control>> { ... }` のようにステレオタイプを付ける。操作は `{method} <U+002B> 操作名() : void` と書く（`+ ` とそのまま書くと「+」の後ろの空白が消える）。クラスどうしは、使う側から使われる側へ向きのある矢印 `C1 --> C2` でつなぐ（画面 → 処理 → データ。処理どうしは呼び出す側 → 呼び出される側）。向きはシーケンス図のメッセージの向きとそろえる。`hide empty members` は書かない。
- 画面遷移図（ステートマシン図。`図/画面遷移図/全体_画面遷移図.puml` の1枚）: 仕様書の 10.1 画面一覧・10.2 の遷移の条件から描く。
  - 画面は `state "<画面名>" as S<画面IDの番号>`（例: 画面ID `MENU-001` のメニュー画面は `state "メニュー画面" as S001`）。画面名は 10.1 の画面名と同じにし、10.1 の画面をすべて載せる（画面IDは連番なので、`S001` から順に並ぶ）。
  - 各画面に `S001 : entry / …`（表示するもの）、`do / …`（その画面でする主な操作。なければ省く）、`exit / …`（離れ方）を書く。「メニューに戻る」（パンくず）の矢印は全画面から引くと読めなくなるので引かず、`exit / メニューに戻る` と書く。
  - 開始は `[*] --> S001`。遷移の矢印 `S002 --> S006 : 生成する` には押すボタン・タブの名前を書き、行き先が条件で変わるときは `\n[条件]` を添える（例: `設定タブ\n[シンプルモード・生成後]`）。
  - 画面の中だけで終わる操作（再生・保存など）は矢印にしない。
- システム概要図・システム構成図（`図/システム図/システム概要図.puml`・`システム構成図.puml` の各1枚。2026-11-19 追加）: 配置図の部品（`actor` / `node` / `rectangle` / `database` / `storage` / `folder` / `artifact`）で描き、名前の前に OpenIconic のアイコン（`<&monitor{scale=3}>` など）を置いて、何の機器・ソフト・データかを絵でも分かるようにする。
  - システム概要図は仕様書の 3.1・3.2 から描く（利用者 → 画面 → アプリの状態 → 処理 → スピーカー・ファイルの流れ）。処理の名前は付録A に合わせ、機能ごとの細かさにはしない。
  - システム構成図は仕様書の 4.2 システム構成表から描く。各部品の名前の先頭に構成表の図番号（①②…）を付け、構成表の行と1対1にする。構成表に載せない開発用のもの（開発ツール・ビルドの道具）は描かない。利用者は番号を付けずに描いてよい。
- ER図（`図/ER図/ER図.puml` の1枚。2026-11-19 追加）: 仕様書の 12.1 テーブル定義・12.2 の関係から描く。エンティティ・キー・線の種類は IDEF1X の記法（リポジトリのルートの `ER図.png` の形）、多重度は UML の表記（下）にする。`!include ../astah-er-style.puml`、枠（mainframe）は付けない。色はクラス図と同じ薄い黄色（#FFFFCC）・太い黒枠。
  - エンティティは `entity "<名称>" as T01 { 主キー -- 属性 }`。名称は 12.1 の「名称（図での名前）」から「（追加）」を除いたもの。属性名は日本語にし、外部キーには ` (FK)` を付ける。同じ親を別の役割で2回参照するときは `役割名.主キー名 (FK)`。主キーに外部キーを含むものは `<<依存>>`（角丸）。
  - キーの値の元になるもの（ジャンル・雰囲気など）は、ファイルがなくてもエンティティにする（T13 ジャンルマスタ・T14 雰囲気マスタ）。主キーに使う値を、どのエンティティにも属さない「宙に浮いた外部キー」にしない（2026-11-19 決定）。
  - 多対多（`0--0`）は描かず、間に関連エンティティ（両方の主キーを主キーに持つ依存エンティティ。例: T15 シンプルモード候補コード進行）を置いて分ける。キーになる値の並び（ID の配列など）も同じく分ける。キーに関わらない設定の値の並び（リズムのテンプレートなど）は分けず、属性名に `[]` を付ける（2026-11-19 決定）。
  - 多重度は UML の「最小..最大」の表記で、線の**両端**に書く（2026-11-20 決定。ユーザーの指示。IDEF1X の黒丸・「P」「Z」と、空でもよい印の白いひし形は使わない）：`1`（ちょうど1件）・`0..1`（0件か1件）・`0..*`（0件以上）・`1..*`（1件以上）。親の側は、外部キーが必ず入るなら `1`、空でもよいなら `0..1`。
  - 線の種類は IDEF1X と同じく、依存リレーション（親の主キーが子の主キーに入る）は実線 `親 "1" -- "0..*" 子`、非依存（子の主キー以外の属性に入る）は破線 `親 "0..1" .. "0..*" 子`。
  - 線にリレーションシップ名（関係の名前。`: 決める` のような動詞）は書かない（2026-11-20 決定。ユーザーの指示）。関係の意味は仕様書 12.2 の文章で伝える。
  - SVG に変換したら、続けて `node docs/基本設計書/tools/er_layout.mjs` で、名前を箱の上に出し、線の端を箱の縁につける（上から入る線が名前とぶつかるときは、左から来る線で箱の左の縁が空いていれば左の縁から入れ、そうでなければ端の近くで直角に曲げて名前の右へずらし、場所が足りなければ箱を広げる）。別々の線が同じ高さ（横位置）で平行に重なるときは、片方を 10 ずらして離す。多重度の文字は、形が決まった線の端の横に置き直し、ほかの線・箱・文字と重なるときは、自分の線に寄せたまま空いている位置へずらす（ほかの線からは 5 以上離し、2本の線の間に挟まってどちらのものか分からなくならないようにする）（2026-11-20。ユーザーの指示）。処理済みの SVG は変えない。手で直さない。
  - 変換したら PNG（`er_layout.mjs --png <フォルダ>`）で、線の端が箱から離れていないか・名前や多重度の文字が線・箱と重なっていないか・多重度の文字がどの線の端のものか分かるかを確かめる（2026-11-19。黒丸が名前の上に浮いていて、一般的な書き方でないと指摘があったため）。
- データ（entity）は「〇〇マスタ」（アプリに同梱した変わらないデータ。例: コード進行マスタ）、「〇〇ファイル」（書き出すファイル）、「〇〇データ」（保存する曲など）のように名付ける。
- SVG への変換（リポジトリのルートで実行）:
  `java -jar tools/plantuml.jar -tsvg -charset UTF-8 "docs/基本設計書/図/**/*.puml"`
  （`図/**.puml` と書くと下の階層のファイルが見つからず「No diagram found」になるので、必ず `**/*.puml` と書く。共通設定ファイルについて「no image」という警告が出るが問題ない）
  ロバストネス図を変換したら、続けて `node docs/基本設計書/tools/robustness_labels.mjs` で線の文を置き直す（変換し直した SVG は印がないので置き直され、ほかの SVG は変わらない）。
