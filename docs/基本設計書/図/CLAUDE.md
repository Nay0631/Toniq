## 設計書の図（PlantUML）

- 図は `docs/基本設計書/図/<図の種類>/` に PlantUML（`.puml`、UTF-8）で書き、同じ名前の `.svg` を同じフォルダに出力する。PNG は使わない。
- 図は仕様書（`docs/基本設計書/仕様書.md`）をもとに描く。コードから直接描かない。機能ID・機能名・日本語の名前は仕様書の機能一覧と名前の対応表に合わせる。
- ファイル名（＝図名）は機能IDで始める。機能の数が変わっても付け直さずに済むよう、機能一覧の No は使わない。
  - ユースケース図: `<グループID>_<グループ名>_ユースケース図`（例: `B01_BPM・曲の基本設定_ユースケース図`）。全体図は `全体_楽曲生成システムToniq_ユースケース図`
  - ロバストネス図・シーケンス図・クラス図: `<機能ID>_<機能名>機能_<図の種類>`（例: `B01-1_BPM選択機能_ロバストネス図`。機能名は仕様書の機能一覧の名前）。クラスの全体図は `全体_クラス図`
- `.puml` を追加・修正したら、対応する `.svg` も作り直す。変換後に `.svg` の中を「Syntax Error」で検索して、エラーが無いことを確かめる。
- 見た目は astah 風にそろえる。`@startuml` の直後で、図の種類ごとの共通設定を `!include` する。図の中に `skinparam` を書かない。
  - ユースケース図: `!include ../astah-usecase-style.puml`、枠は `mainframe **uc** <図名>`
  - ロバストネス図: `!include ../astah-robustness-style.puml`、枠は `mainframe **uc** <図名>`
  - シーケンス図: `!include ../astah-sequence-style.puml`、枠は `mainframe sd <図名>`
  - クラス図: `!include ../astah-class-style.puml`、枠は `mainframe **pkg**`
  - 画面遷移図: `!include ../astah-state-style.puml`、枠は `mainframe **stm** <図名>`
- `title` は使わない（枠に図名を入れる）。
- 共通設定ファイル（`astah-*.puml`）には `@startuml` / `@enduml` を書かない。
- 名前は日本語で書く。画面・処理・データ・クラス・操作・属性に、コードの識別子（`SimpleScreen`、`setState()` など）は使わず、日本語の名詞・動詞にする（例: 「シンプルモード画面」「コード進行を再抽選する()」「コード進行マスタ」）。同じものはどの図でも同じ名前にする。
- 細かさは利用者の操作の単位にそろえる。画面の描き直し・状態の読み書きなど、画面の中の細かい呼び出しは書かない。
- ユースケース図: 利用者は `actor "利用者" as A1`。システムの範囲は `rectangle "<システム名>" { usecase "<機能名>" as UC1 }`。利用者とユースケースは `A1 -- UC1`（矢印なし）でつなぐ。
- ロバストネス図: `actor` / `boundary`（画面）/ `control`（処理）/ `entity`（データ）を使う。線は向きのある矢印 `-->` で書き、線には操作や条件を書く（例: `A1 --> B1 : 生成するボタンを押下する`）。
  - つないでよいのは、利用者 → 画面、画面 → 処理、処理 → 処理、処理 → データ、処理 → 画面（処理の結果として別の画面へ移る・画面に表示する）。利用者 → 処理・データ、画面 → 画面、画面 → データはつながない（間に処理を置く）。
  - 入力が足りないなどで先へ進めないときは、処理の自己ループで書く（例: `C1 --> C1 : ファイルが選択されていない`）。
- シーケンス図: 参加者の表示名は先頭に「:」を付ける（`actor ":利用者" as L1`、`boundary ":シンプルモード画面" as L2`）。メッセージ名は `操作名() : void` の形にする（例: `L1 -> L2 : 再生ボタンを押下する() : void`）。メッセージを受け取った側を `activate` / `deactivate` する。`alt` などの分岐の中で `activate` したものは、その分岐の中で `deactivate` する。
- クラス図: `class "クラス名" as C1 <<control>> { ... }` のようにステレオタイプを付ける。操作は `{method} <U+002B> 操作名() : void` と書く（`+ ` とそのまま書くと「+」の後ろの空白が消える）。クラスどうしは、使う側から使われる側へ向きのある矢印 `C1 --> C2` でつなぐ（画面 → 処理 → データ。処理どうしは呼び出す側 → 呼び出される側）。向きはシーケンス図のメッセージの向きとそろえる。`hide empty members` は書かない。
- 画面遷移図（ステートマシン図。`図/画面遷移図/全体_画面遷移図.puml` の1枚）: 仕様書の 10.1 画面一覧・10.2 の遷移の条件から描く。
  - 画面は `state "<画面名>" as S<画面ID>`（例: `state "メニュー画面" as S001`）。画面名は 10.1 の画面名と同じにし、10.1 の画面をすべて載せる（欠番の画面は載せない）。
  - 各画面に `S001 : entry / …`（表示するもの）、`do / …`（その画面でする主な操作。なければ省く）、`exit / …`（離れ方）を書く。「メニューに戻る」（パンくず）の矢印は全画面から引くと読めなくなるので引かず、`exit / メニューに戻る` と書く。
  - 開始は `[*] --> S001`。遷移の矢印 `S002 --> S006 : 生成する` には押すボタン・タブの名前を書き、行き先が条件で変わるときは `\n[条件]` を添える（例: `設定タブ\n[シンプルモード・生成後]`）。
  - 画面の中だけで終わる操作（再生・保存など）は矢印にしない。
- データ（entity）は「〇〇マスタ」（アプリに同梱した変わらないデータ。例: コード進行マスタ）、「〇〇ファイル」（書き出すファイル）、「〇〇データ」（保存する曲など）のように名付ける。
- SVG への変換（リポジトリのルートで実行）:
  `java -jar tools/plantuml.jar -tsvg -charset UTF-8 "docs/基本設計書/図/**/*.puml"`
  （`図/**.puml` と書くと下の階層のファイルが見つからず「No diagram found」になるので、必ず `**/*.puml` と書く。共通設定ファイルについて「no image」という警告が出るが問題ない）
