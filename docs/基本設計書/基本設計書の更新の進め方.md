# 基本設計書の更新の進め方

Claude Code で、仕様書.md・図・docx を更新するときの手順です。細かい決まりは [基本設計書の作成手順.md](基本設計書の作成手順.md)、Claude Code が行う中身は `.claude/skills/` の各 `SKILL.md` にあります。

## いつ行うか

| 作業 | タイミング |
|---|---|
| 1. 仕様書.md の修正 | ほかのメンバーの変更が `main` にマージされたあと（区切りのよいとき。週1回など） |
| 2. 図の作成・修正 | 1 のあと、毎回続けて行う |
| 3. 基本設計書（docx）の作成 | 提出・レビューの前だけ（毎回は作らない） |
| 4. ガントチャートの更新 | 2 のあと（3 を作らない回も行う） |

順番は必ず **1 → 2 → 3**。図は仕様書から描き、docx は仕様書と図から作るためです。4 は 2 のあとならいつでもよい（足す行は「図まで作り終えた機能」として進捗 100% にするため、図より前には行わない）。

## はじめに1回だけ

- Java と Python を入れる（[Java・Pythonのインストール手順.md](Java・Pythonのインストール手順.md)）。

## 手順とプロンプト

プロンプトは日本語の文で頼めます。右の列のコマンド（`/` で始まるもの）を入力しても、同じ作業になります。

### 1. 仕様書.md の修正

**手順**

1. Claude Code に下のプロンプトを送る。前回の基準のコミットから今の `origin/main` までの変更が、仕様書.md に反映される（`git fetch` も Claude Code が行う）。
2. 報告の「図の更新が必要な機能」を確認する。
3. 仕様書.md の変更を見て、問題がなければコミットする。

**プロンプト**

| 頼み方 | 同じ意味のコマンド |
|---|---|
| `仕様書.md を最新のコードに合わせて更新して` | `/update-spec` |

### 2. 図の作成・修正

**手順**

1. Claude Code に下のプロンプトを送る。普段は、1 で「図の更新が必要」とされた図だけが直される。
2. 作った・直した図（.svg）を VS Code で開いて確認する。
3. 問題がなければコミットする。

**プロンプト**

| 場合 | 頼み方 | 同じ意味のコマンド |
|---|---|---|
| 普段（1 のあと） | `仕様書.md をもとに図を更新して` | `/update-diagrams` |
| 特定の機能だけ | `B01-1 と C01-7 の図を作り直して` | `/update-diagrams B01-1 C01-7` |
| 特定の種類の図だけ | `システム図と ER図を作り直して` | `/update-diagrams システム図 ER図` |
| 全部作り直す（ユースケース図・機能の図・画面遷移図・システム概要図・システム構成図・ER図） | `図を全部作り直して` | `/update-diagrams all` |

### 3. 基本設計書（docx）の作成

**手順**

1. Claude Code に下のプロンプトを送る。版数・改訂の概要は自動で決まり、作り始める前に確認を求められるので、よければ「はい」と答える。
2. 2〜3分待つ。
3. できた docx（`作成ファイル/<版数>_2026_卒研_基本設計書(R4SA_アプリオリ)_仕様書から作成.docx`。ファイル名の先頭の2桁が今回の版数）を Word で開き、表紙・改訂履歴・目次・図のページを確認する。
4. 前の版の docx（先頭の2桁が違うもの）は残ったままになる。残すか消すかを決める（消してもコミットの履歴には残る）。
5. 問題がなければコミットする。docx は約20MB なので、push は提出版など区切りのときだけにする。

**プロンプト**

| 場合 | 頼み方 | 同じ意味のコマンド |
|---|---|---|
| 普段 | `仕様書.md と図から基本設計書を作り直して` | `/build-design-doc` |
| 版数・改訂の概要を決めて作る | `版数 03、改訂の概要「MP3エクスポートとキー・スケール試聴を追加」で基本設計書を作り直して` | `/build-design-doc 03 MP3エクスポートとキー・スケール試聴を追加` |

### 4. ガントチャートの更新

**手順**

1. Excel でガントチャートを閉じてから、Claude Code に下のプロンプトを送る。仕様書.md にあってガントチャートにない機能・画面・テーブルの行（2.機能設計・3.画面設計・4.データベース設計・7.各種設計図）が足され、仕様書と名前が違う行は仕様書の名前に直り、仕様書から外した機能などの行は消え、「（xxxxx）」「（T_xxxx)」に英名が入る。
2. 足す行の中身（担当者・日付）が示されるので、よければ「はい」と答える。
3. 更新が終わると、ファイル名の最後の番号が1つ上がる（`ガントチャート(アプリオリ)1114.xlsx` → `…1115.xlsx`）。何も変わらなかったときは上がらない。
4. 新しい名前のガントチャートを Excel で開いて、足した行と書式を確認する。シート「2027」は触らない（消した行を参照している行は #REF! になるが、直さなくてよい）。
5. 問題がなければコミットする（前の名前のファイルの削除と、新しい名前のファイルの追加の両方をコミットする）。

**プロンプト**

| 頼み方 | 同じ意味のコマンド |
|---|---|
| `ガントチャートを仕様書.md に合わせて更新して` | `/update-gantt` |

機能の英名は `tools/gantt_names.tsv` に1行ずつ書いてあります（機能が増えたら Claude Code が足します）。

## 注意

- 4つの作業はそれぞれ別に頼み、1つ終わるごとに中身を確認してコミットします（まとめて頼むと、どこで間違えたか分かりにくい）。
- システムの開発のためのテスト・確認に作ったもの（テスト中の機能切替・自動チェック・メロディの評価・一括計測など）は基本設計書に載せません。1 で Claude Code が外します（決まりは作成手順の「0. 決まっていること」の「載せないもの」）。
- docx は直接直さないでください。直したいところは仕様書.md・図で直し、3 で作り直します。
- 手本の `作成ファイル/04_2026_卒研_基本設計書(R4SA_アプリオリ).docx` は消さないでください（docx の書式の元です）。
- コミット・push は自分で行います（Claude Code は行いません）。
