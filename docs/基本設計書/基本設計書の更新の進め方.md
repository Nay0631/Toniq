# 基本設計書の更新の進め方

Claude Code で、仕様書.md・図・docx を更新するときの手順です。細かい決まりは [基本設計書の作成手順.md](基本設計書の作成手順.md)、Claude Code が行う中身は `.claude/skills/` の各 `SKILL.md` にあります。

## いつ行うか

| 作業 | タイミング |
|---|---|
| 1. 仕様書.md の修正 | ほかのメンバーの変更が `main` にマージされたあと（区切りのよいとき。週1回など） |
| 2. 図の作成・修正 | 1 のあと、毎回続けて行う |
| 3. 基本設計書（docx）の作成 | 提出・レビューの前だけ（毎回は作らない） |

順番は必ず **1 → 2 → 3**。図は仕様書から描き、docx は仕様書と図から作るためです。

## はじめに1回だけ

- Java と Python を入れる（[Java・Pythonのインストール手順.md](Java・Pythonのインストール手順.md)）。

## 手順とプロンプト

プロンプトは日本語の文で頼めます。右の列のコマンド（`/` で始まるもの）を入力しても、同じ作業になります。

### 1. 仕様書.md の修正

**手順**

1. Claude Code に下のプロンプトを送る。前回の基準のコミットから今の `origin/main` までの変更が、仕様書.md に反映される（`git fetch` も Claude Code が行う）。
2. 報告の「図の更新が必要な機能」を確認する。
3. 仕様書.md の変更を見て、問題がなければコミットする。

**プロンプト**

| 頼み方 | 同じ意味のコマンド |
|---|---|
| `仕様書.md を最新のコードに合わせて更新して` | `/update-spec` |

### 2. 図の作成・修正

**手順**

1. Claude Code に下のプロンプトを送る。普段は、1 で「図の更新が必要」とされた図だけが直される。
2. 作った・直した図（.svg）を VS Code で開いて確認する。
3. 問題がなければコミットする。

**プロンプト**

| 場合 | 頼み方 | 同じ意味のコマンド |
|---|---|---|
| 普段（1 のあと） | `仕様書.md をもとに図を更新して` | `/update-diagrams` |
| 特定の機能だけ | `B01-1 と C01-7 の図を作り直して` | `/update-diagrams B01-1 C01-7` |
| 全部作り直す | `図を全部作り直して` | `/update-diagrams all` |

### 3. 基本設計書（docx）の作成

**手順**

1. Claude Code に下のプロンプトを送る。版数・改訂の概要は自動で決まり、作り始める前に確認を求められるので、よければ「はい」と答える。
2. 2〜3分待つ。
3. できた docx を Word で開き、表紙・改訂履歴・目次・図のページを確認する。
4. 問題がなければコミットする。docx は約14MB なので、push は提出版など区切りのときだけにする。

**プロンプト**

| 場合 | 頼み方 | 同じ意味のコマンド |
|---|---|---|
| 普段 | `仕様書.md と図から基本設計書を作り直して` | `/build-design-doc` |
| 版数・改訂の概要を決めて作る | `版数 03、改訂の概要「MP3エクスポートとキー・スケール試聴を追加」で基本設計書を作り直して` | `/build-design-doc 03 MP3エクスポートとキー・スケール試聴を追加` |

## 注意

- 3つの作業はそれぞれ別に頼み、1つ終わるごとに中身を確認してコミットします（まとめて頼むと、どこで間違えたか分かりにくい）。
- docx は直接直さないでください。直したいところは仕様書.md・図で直し、3 で作り直します。
- 手本の `作成ファイル/04_2026_卒研_基本設計書(R4SA_アプリオリ).docx` は消さないでください（docx の書式の元です）。
- コミット・push は自分で行います（Claude Code は行いません）。
