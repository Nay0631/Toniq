# 仕様書.md から基本設計書（docx）を作る

docx は**直接直さず**、仕様書.md と図から作り直す。毎回この手順どおりに行う。
最初に `docs/基本設計書/基本設計書の作成手順.md` の「5. docx を作る」を読む。

## 0. 前提の確認（ここで止まることがある）

次を全部確かめ、1つでも欠けていたら**スクリプトを動かさずに止め**、足りないものとその入れ方をユーザーに伝える。

| 必要なもの | 確かめ方（PowerShell） | ないとき |
|---|---|---|
| Java | `Get-Command java` | `winget install EclipseAdoptium.Temurin.21.JRE` |
| Python（py ランチャー） | `Get-Command py` | `winget install Python.Python.3.12`（`python` が WindowsApps の仮のものだけでは動かない） |
| Word | `Test-Path "C:\Program Files\Microsoft Office"` | Microsoft 365 の Word を入れる |
| 手本の docx | `作成ファイル/04_2026_卒研_基本設計書(R4SA_アプリオリ).docx` があるか | Git から戻す（`git restore`）。**このファイルは消さない** |

コミット・push はしない。

## 1. 仕様書・図が最新か確かめる

1. `git fetch origin` のあと、仕様書.md の基準のコミットと `git rev-parse --short origin/main` を比べる。違えば「仕様書が `origin/main` より古い」とユーザーに伝え、先に `/update-spec` を行うか、このまま作るかを聞く。
2. 仕様書.md の付録C の「図への反映」に `要：…` が残っていれば、先に `/update-diagrams` を行うか、このまま作るかを聞く。
3. 仕様書.md の 5.2 で見出しに「（未実装）」がある機能と、`docs/基本設計書/tools/build_docx.py` の `FIG_INTRO` と6章の置き換えの文（`未実装の …` の文）に書かれた機能IDが一致しているか比べる。違えばスクリプトの文を仕様書に合わせて直す（未実装がなくなったら「未実装の … は」の文ごと外し、未実装の機能ができたら「未実装の ○○ は実装後に作成する。」の文を足す）。直したことは報告に書く。

## 2. 版数と改訂の概要を決める

- 版数（`-Rev`）：引数があればそれ。なければ `基本設計書の作成手順.md` の「進み具合」の「5. docx を作る」の行にある前回の版（例「版 02」）の次（`03`）。2桁で書く。
- 改訂の概要（`-RevNote`）：引数があればそれ。なければ `仕様書.md（基準：main <基準のコミット>）の内容で改訂。` に続けて、前回 docx を作ったあとの付録C の行の内容を1文に縮めて書く。
- 決めた版数と改訂の概要は、スクリプトを動かす前にユーザーに示す（違っていれば直してもらう）。

## 3. スクリプトを動かす

リポジトリのルートで、PowerShell からタイムアウトを長め（10分）にして実行する。

```
powershell -ExecutionPolicy Bypass -File "docs/基本設計書/tools/build_docx.ps1" -Rev <版数> -RevNote "<改訂の概要>"
```

- 出力の最後の「ページ数」を控える。前回（進み具合の表に書いてある）と大きく違えば、理由を確かめる。
- `assert` で止まったら、手本の docx が編集されて段落の番号がずれている（作成手順の「5-3」）。勝手に番号を直さず、ユーザーに知らせる。
- Word が残って次の実行が失敗するときは、ユーザーに確認してから `WINWORD` のプロセスを止める。

## 4. できた docx を確かめる

1. スクリプトの外で、PowerShell から Word を開いて PDF にする（`ExportAsFixedFormat(<PDFのパス>, 17)`。PDF はスクラッチパッドに置く）。
2. 表紙（日付）・改訂履歴（今回の行）・目次・機能定義の表を1つ・図のページを1つ、ページの画像で確かめる。ページを画像にできない環境なら、そのことを報告に書き、ユーザーに Word で目で確かめてもらう。

## 5. 記録を更新する

`基本設計書の作成手順.md` の「進み具合」の「5. docx を作る」の行を、`版 <版数> を作成済（<今日の日付>、仕様書.md 基準 main <基準のコミット>、<ページ数>ページ）` に書き換える。

## 6. 報告（毎回この形）

```
## 基本設計書（docx）の作成
- 版数／改訂の概要：
- 基準のコード：main <コミット>
- ページ数：N（前回 M）
- build_docx.py で直したこと：<あれば>
- 確かめたページ：<表紙・改訂履歴・目次 … ／確かめられなかった理由>
```

docx は約14MB。リポジトリは公開されているので、push は提出版など区切りのときだけにするよう、報告で一言添える。最後に、CLAUDE.md の決まりどおりコミットメッセージ案（`docs:` で始める）を示す。
