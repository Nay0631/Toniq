# ガントチャートを仕様書.md に合わせて更新する

行うのは、仕様書.md の更新（`/update-spec`）と図の更新（`/update-diagrams`）のあと（足す行は「図まで作り終えた機能」として進捗 100% にするため）。docx（`/build-design-doc`）の前でも後でもよい。
コミット・push はしない。

## 絶対にしてはいけないこと

- **Excel のフォーマットを崩す。** xlsx の中身（XML）を直接書き換えない・openpyxl で保存しない。書き込みは必ず `tools/gantt_apply.ps1`（Excel 自身に操作させる）で行う。
- 既にある行を並べ替える。番号は欠番を作らず、行を消したら後ろの行の番号を詰めて 01 からの連番にする（2026-11-20 決定。下の `[要振り直し]`）。
- シート「2027」を直す（「2026」のセルを数式で参照しているだけで、パスワードで保護されている）。

## 1. 突き合わせる（gantt_check.py）

リポジトリのルートで、PowerShell から実行する（読むだけ）。

```
[Console]::OutputEncoding = [Text.Encoding]::UTF8; py docs/基本設計書/tools/gantt_check.py
```

節ごとに、仕様書にあってガントチャートにない機能・画面・テーブル（`[要追加]`／`[要確認]`）、仕様書と名前が違う行（`[要改名]`）、仕様書から外した機能・画面・テーブルの行（`[要削除]`）、担当者（C列）の数、開始〜終了（E列・F列）の組の数、最後の行・次の番号（消さない行の数 + 1）を出す。番号が 01 からの連番になっていない行は `[要振り直し]` として、消す行を除いて詰めた新しい番号を出す。ほかに「西園」の残り、「（xxxxx）」「（T_xxxx)」の残りを出す。

- `[NG] gantt_names.tsv にない機能`・`[?] 対応表にない`：`docs/基本設計書/tools/gantt_names.tsv`（機能ID・仕様書の機能名・ガントチャートでの別名・英名）に行を足してから、もう一度実行する。英名は仕様書に書いてあればそれ、なければ機能を表す PascalCase の英語（コードの名前に近いもの。例 `TapTempo`・`UndoRedo`）。
- 画面（3.画面設計）は名前の違い（「生成完了」と「生成後」など）だけなら足さない。本当に新しい画面だけ、隠してある雛形の行（`3-11.○○機能画面` …）を使うか、節の最後に足す。
- テーブル（4.データベース設計）は仕様書の 12.1 の ID（T01〜）と突き合わせる。足すときは**隠してある雛形の行**（`4-13.○○テーブル（T_xxxx)` …。グループ化して畳んである）を上から使い、`set` で B〜F を書いてから `show` で表示する（グループも外れて、上の見えている行と同じ状態になる）。B 列は `4-13.genre_scalesテーブル（T_genre_scales)` の形（英名は gantt_names.tsv）。仕様書にないテーブルの行は `[要削除]` として消す（musicfile・AppState は 2026-11-20 に消した）。
- ユースケース図・ユースケース記述は、仕様書のシステム（5.1 のグループ）が増えたときだけ足す（ガントチャートは別の名前で書いているので、数と中身で判断する）。

## 2. 計画（JSON）を作る

作業用フォルダ（スクラッチパッド）に `plan.json` を書く。形は `gantt_apply.ps1` の先頭のコメントのとおり（`replace` / `set` / `show` / `insert`）。雛形の行がある節（3章・4章・ユースケース）は雛形の行を使い、ない節（2章・7章のクラス図〜シーケンス図）は `insert` で節の最後に足す。行番号は**今のファイルの行番号**で書く（挿入は下の節から当てるので互いにずれない）。

決まり（ユーザーの指示。2026-11-20）：

| 列 | 足す行に入れる値 |
|---|---|
| B | 節の番号の形（`2-56.拍子選択機能`、7章は `7-56.…`）。番号は節の「次の番号」から。シーケンス図の節は既存の行と同じく `7-56.拍子選択機能 （MeterSelection）`（全角の括弧の前に半角スペース） |
| C | 「根井」「西薗」「小手川」を、足す行全体で**ほぼ均等に**割り振る（ちょうど同じ数にはしない。例 24行なら 9・8・7）。同じ機能の行が全部同じ人にならないようにずらす |
| D | すべて `1`（100%） |
| E・F | **ガントチャートを更新した日（作業した当日）**を開始・終了の両方に入れる（例 当日が 2026-11-27 なら E・F とも `"2026-11-27"`）。その節に既にある組からは選ばない（2026-11-27 決定。以前は既にある組から少ない組へ入れていた）。足す行は節の最後に入り、既にある行より日付が後になるので、昇順（下の `[要並べ直し]`）は崩れない |

ほかに：

- `[要改名]` の行は、出た新しい名前に `set` で書き換える（2〜9章の機能名・3章の画面名・7章のシステム名を仕様書の名前にそろえる。4章のテーブルは実体の英名で書く決まりなので改名しない。ただし実体の英名が変わったら改名する（例：T11 lidless_presets → grow_presets。2026-11-23）。そのときは gantt_names.tsv の「英名」を新しい名前にし、新しい英名も「別名」に足す（`gantt_check.py` は 4章の行を「仕様書の名前」と「別名」だけで照合するので、足さないと `[要追加]` になる）。4章の行の名前が「英名」と違うと `gantt_check.py` が `[要改名]` で新しい名前（`テーブル` の前と `T_` のあとの両方）を出す）。古い名前は gantt_names.tsv の「別名」に書いておく。
- `[要削除]` の行は `delete` で消す（2026-11-20 決定：隠さずに消す）。シート「2027」は触らない（2026-11-20 決定）ので、その行を参照している「2027」の行は `#REF!` になる（スクリプトが行番号を出す。直さなくてよい）。仕様書から外した機能・画面・テーブルは、gantt_names.tsv に ID「-」で書いておく。
- `[要振り直し]` の行は、出た新しい番号（B 列）に `set` で書き換える（2026-11-20 決定：欠番を作らない）。番号は `[要削除]` の行を除いて詰めてあり、`[要改名]` と重なる行は改名後の名前になっているので、削除・改名と同じ計画で当ててよい（同じ行の改名の `set` は振り直しの `set` 1つにまとめる）。足す行の番号は「次の番号」から。
- 開始〜終了（E・F）は、節ごとに番号の順（上から）で昇順にする（2026-11-24 決定：上から作業が進むように見せる）。行は並べ替えず、節の組と組ごとの件数はそのままで、上の行から早い組を割り当て直す。`gantt_check.py` が昇順でない行を `[要並べ直し]` として新しい日付つきで出すので、`set` で E・F を書き換える。足す行は更新した日の日付にする（上の表の E・F）ので、既にある行の割り当て直しには含めない（既にある行だけで昇順にし、足す行はその下に当日の日付で置く。試しに当てた写しで `[要並べ直し]` が出なければよい）。担当者（C 列）は動かさない。8.プログラミング・9.各種テストは担当者ごとの予定なので、**担当者ごとに**（その人の行の中で、その人の組と件数のまま）昇順にする（節全体で昇順にすると担当者の時期ごとの件数が偏るため。2026-11-24 決定）。9章のテストが同じ機能の 8章のプログラミングの終わり以前に始まると `[要確認]` が出るので、ユーザーに知らせる。
- `gantt_check.py --json <ファイル>` の `renames`・`deletes`・`renumbers`・`date_orders` から計画を作ってよい。
- 「西園」は「西薗」に直す（`replace`。シート 2026 の定数のセルだけ）。
- 「（xxxxx）」は gantt_names.tsv の英名、「（T_xxxx)」はテーブルの名前（`4-01.chord_progressionsテーブル（T_chord_progressions)` のように `T_` ＋行のテーブル名）に書き換える（`set`）。隠してある雛形の行（`○○`）は直さない。

計画の中身（足す行の B〜F・書き換える行の数）は、当てる前にユーザーに示す。

## 3. 写しで試してから当てる（gantt_apply.ps1）

```
powershell -ExecutionPolicy Bypass -File "docs/基本設計書/tools/gantt_apply.ps1" -Plan <plan.json> -Out <作業用フォルダ>/test.xlsx
py docs/基本設計書/tools/gantt_check.py --xlsx <作業用フォルダ>/test.xlsx
```

写し（`-Out`）で `[要追加]`・`[要修正]`・`[要記入]`・`[要振り直し]`・`[要並べ直し]` がなくなったのを確かめてから、`-Out` を外して本物に当て、もう一度 `gantt_check.py` を実行する。

- 「Excel で開かれています」で止まったら、ユーザーに Excel を閉じてもらう（ロックファイル `~$…` が残っているだけで Excel が動いていなければ止まらない）。
- 当てる前に、元の xlsx を作業用フォルダに写して控える（やり直すとき用）。
- 同じ計画を2回当てない（行が二重に増える）。失敗したら控えから戻してやり直す。
- `gantt_apply.ps1` は最後に **B 列（タスク名）の幅を、いちばん長いタスク名が途切れない幅に合わせる**（2026-11-20 決定。6 行目の見出しから下の B 列を Excel の自動調整で測り、余白 2 を足す。下限 20）。行を足す・改名したあとの長さで測るので、計画に幅のことは書かなくてよい。結果は「B 列の幅: 前 → 後」と出るので報告に入れる。
- `gantt_check.py` が全部 `[OK]` で当てる計画がないときも、空の計画（`{}`）で `gantt_apply.ps1` を本物に当てて B 列の幅だけ合わせる（幅が変わらなければ何も変わっていない）。

## 4. ファイル名の番号を1つ上げる（gantt_bump.ps1）

更新（本物への `gantt_apply.ps1`）がすべて終わったら、**1回の更新につき1回だけ**、ファイル名の最後の番号を1つ上げる（`ガントチャート(アプリオリ)1114.xlsx` → `…1115.xlsx`。2026-11-20 決定）。何も変えなかった（`gantt_check.py` が全部 `[OK]` で当てる計画がなく、B 列の幅も変わらなかった）ときは上げない。B 列の幅だけ変わったときも1回の更新として上げる。

```
powershell -ExecutionPolicy Bypass -File "docs/基本設計書/tools/gantt_bump.ps1"
```

Excel で開かれていると止まるので、閉じてもらってから実行する。`git mv` はしない（コミットはユーザーが行う）。

## 5. 報告

足した行（節・番号・担当者・日付）、改名・削除した行、番号を振り直した行の数（節ごと）、日付を並べ直した行の数（節ごと）、書き換えた行の数、直した「西園」の数、B 列の幅（前 → 後）、新しいファイル名、`gantt_check.py` の結果を報告する。
